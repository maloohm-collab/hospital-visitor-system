# Hospital Visitor Management System (HVMS)

منظومة زوار المستشفى — تطبيق Flutter بواجهة عربية من اليمين إلى اليسار.

## النطاق المعتمد
- دخول ضابط الأمن باسم مستخدم وكلمة مرور لحساب تنشئه الإدارة.
- تسجيل رقم الغرفة وعدد الزوار.
- تسجيل التاريخ ووقت الدخول والخروج تلقائيًا.
- إضافة ملاحظات عند الحاجة.
- إرسال سجل الحركة إلى المشرف داخل التطبيق.
- مراجعة المشرف للتقرير وإحالته إلى الإدارة عند الحاجة.
- صلاحيات كاملة للإدارة لإدارة حسابات الضباط والمشرفين والسجلات والصلاحيات.
- تقارير قابلة للحفظ بصيغة Excel أو PDF.

## البنية التقنية
- Flutter / Dart للواجهة.
- Firebase Authentication وCloud Firestore خياران للبنية المتصلة بالإنترنت.
- لأن Firebase Authentication لا يوفر اسم المستخدم وكلمة المرور مباشرةً كخيار مستقل، يجب اختيار آلية آمنة لربط اسم المستخدم بحساب المصادقة قبل تفعيل الدخول؛ لا تُحفظ كلمات المرور في Firestore.

## حالة التنفيذ الحالية
الواجهات أولية فقط. نموذج حركة الزوار يعرض الحقول المعتمدة ويسمح بمعاينة تسجيل أوقات الدخول والخروج داخل الشاشة، لكن الحفظ والإرسال وتسجيل الدخول الفعلي لم تُربط بعد بالخدمات عبر الإنترنت. لا تعتبر أي رسالة نجاح حالية إثباتًا بأن البيانات حُفظت.

## الخطوات التالية ضمن النطاق المعتمد
1. تثبيت بنية بيانات الزيارة وحالات التقرير: مسودة/مرسل للمشرف/محال للإدارة.
2. تحديد آلية مصادقة آمنة لحسابات اسم المستخدم وكلمة المرور التي تنشئها الإدارة.
3. ربط السجلات والتقارير بقاعدة البيانات عبر الإنترنت وتطبيق صلاحيات كل دور.
4. إنشاء تصدير Excel وPDF.
5. تشغيل التحليل والاختبارات بعد توفر بيئة Flutter وإعدادات Firebase.

## الخصوصية والأمان
- بيانات حركة الزوار حساسة؛ يجب تقييد قراءتها وتعديلها وفق دور الحساب.
- لا تُمنح صلاحيات الإدارة بناءً على قيمة يحددها المستخدم داخل الواجهة.
- لا تُرفع مفاتيح خاصة أو ملفات أسرار إلى المستودع.
