# نشر تحسينات مباشرة العمل على Firebase

تتضمن هذه التغييرات ملفات تطبيق Flutter وقواعد Firestore والفهارس ووظيفة مجدولة لإغلاق المناوبات المنتهية.

## 1. نشر قواعد Firestore والفهارس

من مجلد المشروع الرئيسي، وبعد التأكد من اختيار مشروع Firebase الصحيح:

```bash
firebase deploy --only firestore:rules,firestore:indexes
```

هذه الخطوة مطلوبة حتى يتمكن ضابط الأمن من:
- رؤية ملاحظاته خلال أول 10 ساعات من إرسالها، حتى بعد انتهاء المناوبة.
- حذف ملاحظته بنفسه حتى الموعد المحفوظ لنهاية يوم الإرسال.
- إبقاء الملاحظات متاحة للمشرفين والإدارة وفق صلاحيات المستلمين.

## 2. نشر الإغلاق التلقائي للمناوبات

توجد وظيفة مجدولة في `functions/index.js` باسم `closeExpiredWorkShifts`. تعمل كل خمس دقائق وتغلق المناوبات التي تجاوزت ثماني ساعات، وتغلق الموقع النشط وتحذف مؤشر المناوبة المفتوحة.

نفّذ:

```bash
cd functions
npm install
cd ..
firebase deploy --only functions:closeExpiredWorkShifts
```

**متطلبات مهمة:** الوظائف المجدولة تستخدم Cloud Scheduler، وقد تتطلب تفعيل خطة Firebase Blaze وربط حساب فوترة بالمشروع. لا يعتبر وجود ملف الوظيفة في GitHub دليلاً على نشرها أو تشغيلها في مشروع Firebase.

## 3. بناء التطبيق

بعد نشر قواعد Firestore والفهارس، شغّل سير عمل Build APK من GitHub Actions على فرع `main`.

ملفات قواعد Firestore والفهارس والوظيفة المجدولة لا تُنشر بمجرد بناء APK؛ لكل منها خطوة النشر أعلاه.
